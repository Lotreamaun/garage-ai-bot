# План разработки: Гараж-бот (тг-бот + mini app)

## 1. Идея

Бот в Telegram + Mini App, который повторяет механику Garagey AI:
пользователь фотографирует машину → фото уходит в vision-модель →
модель оценивает уникальность/марку/редкость → карточка машины
добавляется в персональный "гараж" пользователя.

Отличия от оригинала: без лимитов на фото, без рекламы/подписки,
работает и на Android, и на iOS (через Telegram).

Цель — пет-проект для себя и друзей, не коммерческий продукт.

## 2. Стек

**Бот:** Python + [python-telegram-bot](https://github.com/python-telegram-bot/python-telegram-bot)
(v20+, полностью асинхронный)
**Mini App:** JS/TS (Node/React), UI в стиле Liquid Glass +
Telegram Web App SDK, задеплоенный на HTTPS
**Бэкенд:** тот же сервис, что и бот — принимает фото, дергает AI,
пишет в БД, отдаёт данные во фронт mini app
**БД:** PostgreSQL (или SQLite на старте)
**Хранилище фото:** S3-совместимое (Selectel/Yandex Object Storage,
либо диск VPS на старте)
**AI (vision):** GigaChat (основной, т.к. уже есть аккаунт/опыт) +
Google Gemini free tier как бэкап, если у GigaChat окажутся
ограничения на vision в freemium
**Хостинг:** VPS в РФ (Timeweb/Selectel)

## 3. Этапы разработки

### Этап 0 — Подготовка
- Завести бота через BotFather, получить токен
- Проверить лимиты GigaChat на vision-запросы (freemium vs платно)
- Поднять VPS, настроить домен + HTTPS (нужно для Mini App)

### Этап 1 — MVP бэкенда
- Эндпоинт приёма фото от бота
- Промпт для AI: разбор фото → структурированный JSON
  (марка, модель, цвет, редкость/оценка уникальности, теги)
- Сохранение фото в объектное хранилище
- Сохранение карточки машины в БД, привязка к user_id

### Этап 2 — Бот (базовый сценарий)

Флоу пользователя:
1. `/start` — бот готов к работе
2. Пользователь просто отправляет фото — автоматически запускается
   распознавание, без дополнительных команд
3. Бот отвечает сообщением: марка/модель машины + оценка
   уникальности (0-100) + кнопка, открывающая карточку этой машины
   в Mini App. Fun-fact/история в это сообщение не входит —
   генерируется отдельным фоновым запросом и подтягивается только
   при открытии карточки в Mini App

Что нужно реализовать:
- Обработчик `/start`
- Обработчик входящих фото (без промежуточных команд/подтверждений)
- Основной запрос к ИИ: марка/модель/год/критерии уникальности —
  без fun-fact, для быстрого ответа пользователю
- Фоновый запрос к ИИ на генерацию fun-fact/истории, привязанный к
  этой же карточке — не блокирует ответ в чате
- Формирование ответного сообщения по шаблону (марка/модель +
  оценка уникальности)
- Inline-кнопка с deep link на Mini App, открывающая конкретную
  карточку машины (полные данные, включая fun-fact — если он уже
  сгенерировался)
- Команда "мой гараж" — список добавленных машин

### Этап 3 — Mini App

Точки входа:
- Обычное открытие Mini App (из меню бота/кнопки) — показывает
  гараж пользователя: карточки всех машин, которые он сфоткал
- Открытие по кнопке из ответного сообщения после фото — сразу
  открывает карточку конкретной машины (deep link)

Экраны:
- "Мой гараж" — сетка/список карточек с фото (дефолтный экран)
- Карточка машины — детали (фото, название, описание, оценка
  уникальности)
- Кнопка "добавить фото" (либо через бота, либо загрузка прямо из
  mini app)

UI-стиль — Liquid Glass (преломление света, "жидкие" нативные
анимации переходов/интеракций). Требует отдельного ресёрча перед
реализацией: как добиться корректного преломления/бликов и плавной
анимации без просадок производительности на телефонах (WebGL/
CSS backdrop-filter/готовые библиотеки — сравнить подходы).

### Этап 4 — Механики для компании друзей
- Общий рейтинг/лента: у кого какие тачки в гараже
- Дедупликация — не даёт добавить одну и ту же машину дважды
  (по номеру, если виден, либо по визуальному сходству)
- Профили друзей — чужой гараж можно посмотреть

### Этап 5 — Полировка
- Обработка ошибок (нечёткое фото, не машина на фото, дубликат)
- Rate limiting на случай спама фото
- Базовая аналитика использования (сколько фото добавлено и т.д.)

## 4. Требования к анализу машины через нейронку

По каждому фото модель должна определить:
- Марку машины
- Модель
- Год выпуска
- Интересный факт/историю/выжимку про конкретную машину
- Оценку уникальности — по кастомному алгоритму (описывается
  отдельным файлом, не отдаётся на откуп самой нейронке)

### Критерии для алгоритма уникальности (веса — в отдельном файле)

- Марка
- Модель
- Год выпуска
- Цвет
- Тираж/количество выпущенных экземпляров
- Распространение на данной территории
- Тюнинг/модификации от заводского вида
- Комплектация/трим-уровень (топовая версия реже базовой)
- Спецсерия/лимитированный выпуск
- Праворульность/нетипичная для региона конфигурация
- Тип силового агрегата (электро/гибрид как локальная редкость)
- Состояние/сохранность (особенно для старых машин)
- Локальная редкость внутри базы гаражей — отдельная механика:
  считается бэкендом по факту накопленных данных (первый экземпляр
  редкой марки в базе даёт бонус), не нейронкой

### Метаданные фото / геолокация

- Обычное фото в Telegram сжимается и лишается EXIF (в т.ч.
  геометок) — источником для критерия "территория" оно быть не
  может
- Решение: город указывается в профиле пользователя один раз
  (базовый вариант); опционально — точная геолокация через
  `LocationManager` Telegram Web App SDK, если добавление фото идёт
  через Mini App
